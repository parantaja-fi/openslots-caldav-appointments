What to observe

Per target (first click, then a second target):


    
  
  • Opened as a separate window, not a tab?
    • 
  
  • The second click reuses that same window?
    • 
  
  • Placed on the right part of the screen?
    • 
  
  • Handle alive after the page loaded? (The log checks 3 s after each navigation; the status shows it live.)
    • 
  
  • COOP header on that page: DevTools in the work window → Network → the document request → response headers.
      The server sends it, so one browser suffices.
    • 
  
  • Notes: login persisted, page rendered correctly, anything odd — above all a click logged as
      reused that leaves the work window where it was: that page has cut its opener link.
    • 



Scenarios:


    
  
  • Relocation: this page moves to the left part; the relocated copy creates the work window, which lands on the right part.
    • 
  
  • Reload: F5 in the relocated copy, then a target — the log says re-acquired by name and no second window appears.
    • 
  
  • Forget handle, then a target: the same.
    • 
  
  • Close the work window yourself, then a target: a new one appears in the same place (created).
    • 
  
  • Close work window, after the window has shown a foreign page: it closes.
    • 
  
  • Pop-ups blocked: close the work window, press “Open GitHub sign-in in 8 s, without a gesture” → blocked,
      and nothing else breaks. (Chrome’s pop-up setting does not block clicks, hence this button; if the browser
      offers to always allow pop-ups here, decline.)
    • 
  
  • Empty-URL open: “Re-acquire by name, no navigation” must leave the work window’s page as it was.
    • 
  
  • Visual: the two windows do not overlap at 1366×768 and at 1920×1080; the wizard is usable at 40 % width.
