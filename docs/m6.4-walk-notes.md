### Walk log

#### Step 1: Create the accounts

Once the accounts are created, the tab should show the selected accounts
beside the ( Github sighup ) and ( Cloudflare signup ) buttons.
That would allow one to verify that the right accounts are selected,
if the user has many (as I do), if they ever need to restart the wizard.

#### Step 2: Fork the project

Ditto.  Instead of "Your fork exist." above the ( Fork it ) button, the created (or selected)
fork should be visible, as an URL, on the right of the ( Fork it ) button.

The ( Fork it ) button should be below the Github username and Fork name inputs fields.

#### Step 3: Your calendars

The "One calendar for both" should be above the "Calendar provider" choice(s)

The system should support having the two calendars at different providers.
This may not be supported by the system yet.
But, in the case of two calendars, there should be separate "Calendar provider"
choice buttons for both of the calendars.

The Google calendar shall have a separate Wizard of its own, in order to create
the project, service account, key.  Maybe a separate "page" on this SPA
(so that is no longer a "single" page to the user, but a second page where
the GUI goes if the user wants to create a new Google Console project,
service account, and key.  For now, there may be a "Create Google credentials" button that temporarily just says "Not implemented yet."

For the Nextcloud, the fields should be as follows:

1. Instructions for finding the calendar address:
   - click https://use23.thegood.cloud/apps/calendar/ (given as a clickable URL, opening on another window)
   - click the calendar's pen icon
   - copy "Internal link"
2. The calendar address field
3. Instructions for creating an app password; the second time a note that the same can be reused, if needed. Essentially moving down from above and augmenting for the second time.
4. Availability *login* field.  Note the lable change, for consistency with the Nextcloud GUI
5. App password field, as is now.

#### Step 4: Your Cloudflare token

Again, we need a deep link button directly to Cloudflare, if we know the slug:

https://dash.cloudflare.com/<slug>/api-tokens/create

If we don't have the slug at this point, then the clicking path:
Dashboard -> Manage account -> Account API tokens -> Create Token

#### Step 5: Email confirmations

Again, a deep link button to Brevo API key:
https://app.brevo.com/settings/keys/api -> + Generate API key

Or, if not available:
Account (on the right up) -> Settings -> SMTP & API -> API keys & MCP -> + Generate API key

In email-confirmations, tab moves forward even when optional fields are not walked even once, and even over the Step 6 fields.  That feels odd.

Either the wizard should keep track of on which fields the cursor has been on and skip them only if both the cursor has been on them and there is a valid value, or, alternatively, never just skip filled fields but always have the same tabbing order.  I am not sure which one is better.

#### Step 7: Write to your fork

The Github form is opened nicely, but the instruction test should highlight the "Only select repositories."  Otherwise it may go unnoticed.

#### Step 8: Switch Pages to GitHub Actions

The title should be "Switch Github Pages to build using GitHub Actions"

At this point I get confused.  There is the custom domain, which I think should be filled, and the HTTPS box.  For now, I stopped here, to continue with a next run.
